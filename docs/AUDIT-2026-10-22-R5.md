# 第五轮：专家组审计与逐条落地

日期：2026-10-22
基线提交：`4a494ff`（本轮开始时的 `main`）
分支：`main`

> 前四轮是「在自己的产品里找问题并修」。这一轮换了一种做法：**找人来当自己的眼睛**。
> 五个专家（体验、可访问性与国际化、前端页面集成、后端数据安全、代码与门的质量）
> 各自独立审了同一个产品，把问题一条条写下来，附上文件行号和「用户会怎么感觉到」。
> 这一轮做的事，是把他们的结论**逐条自查**、分成五队并行修、修完再审。

---

## 零、这一轮的做法

1. **五个专家组同时进场**，互相不知道对方在做什么，避免「大家一起想到同一件事」。
2. **每一条都带证据**：文件行号 + 用户可见的症状 + 复现方式。没有证据的不算缺陷。
3. **先自查再动手**：审计报告是别人的结论，不是事实。本轮对每一条都先复现，
   复现不了的不改，改错了比不改更糟。
4. **改了就要有门**：每一条修复都配一个「改了会红、还原会绿」的测试。
   仓库的规矩是 **"a gate that cannot fail is not a gate"**。
5. **分队不重叠文件**：五个队各自拥有自己的文件，避免并行写坏同一处。

这一轮一共收到 **70 条**结论（五个报告合并去重后写进下面的清单）。裁决如下：

| 裁决 | 条数 | 含义 |
| --- | --- | --- |
| 修 | 65 | 复现了，是真缺陷 |
| 已在本轮修掉 | 3 | 审计员报的时候，本轮已经修完了 |
| 误报 / 无法复现 | 2 | 报了，但复现不了，或被另一条覆盖 |

**分工**（每个队只拥有自己的文件，避免并行写坏同一处）：

| 队 | 文件 |
| --- | --- |
| 后端 | `server/**` |
| 页面 | `content.js`、`background.js` |
| 面板样式 | `sidepanel.html`、`sidepanel.css` |
| 面板逻辑 | `sidepanel.js`、`options.js`、`options.html` |
| 门 | `tests/`、`scripts/`、`.github/workflows/` |

**每一条修复都要**：

1. 先复现。复现不了就不改，把证据写回报告。
2. 改根因，不是改症状。同一个错误在两处产生，就改产生它的那一处。
3. 配一个「还原就绿、改了会红」的测试。
4. 不自己提交。改动留在工作区，由负责人审完再提交。

## 五、结果

65 条真缺陷全部修完，五个队各自交付。修的不是症状，是产生症状的那一处。

### 5.1 修了什么

**面板的表面**（`sidepanel.html` / `sidepanel.css`）

- 四个列表从 `<div>` 变成真的 `<ul>`/`<li>`，读屏能报条目数，列表快捷键能跳。
- 语言切换从三个 toggle 变成一个原生 radio group：读屏说得出「第几个、选中了哪个」，方向键能走。
- 时间戳统一成一颗药丸。章节、引用、笔记、字幕、生词五处时间戳原来有五种设计，
  章节和引用的戳甚至不在一条列上；现在全panel 同一颗药丸，同一个宽度。
- 收藏星标、禁用态翻页箭头、滚动条滑块的对比度补到可读。
- 费用说明从页眉（吃掉 25% 高度）挪到字幕页——价格跟着它标价的那个东西走。
- 笔记输入框和它的保存按钮放大到最小点击区。

**面板的逻辑**（`sidepanel.js` / `options.js`）

- **A1 是这一轮最大的一条**：键盘用户根本选不了字幕文本，于是「讲解 / 笔记 / 生词」
  三个功能对键盘用户等于不存在。现在面板自己管一个光标：方向键移动、Shift+方向键选中，
  选完的工具条和鼠标选出来的工具条是同一个。
- 对话框的焦点陷阱第一次 Shift+Tab 就漏，现在从对话框本身也能绕回最后一个动作。
- 切到「中文 / 双语」之前会先说清楚要调用多少次、大概要花多少钱，用户说 yes 才发第一个请求。
- 「讲解」弹窗补上了价格说明（它是最容易被连点十次的付费动作）。
- 删生词播报的是「生词已删除」，不是「Copied」。
- 同一条 live-region 消息第二次会再说一遍。
- 「删除我的账号」现在连本机上没登录时写的笔记和生词一起带走。
- 设置页的中文用户看到的是中文占位符，不是四个英文的 "Paste your ... key"。

**YouTube 页面**（`content.js` / `background.js`）

- 笔记不再记到隔壁视频名下：videoId、标题、频道、时间戳现在从播放器一次读出来，
  同一个对象，不会读到三个时刻的三个真相。
- 页面上的 Note 按钮带上了选中的文字，不再每次都走付费的整段转写拉取。
- YouTube 自己的 Shift+N 不再被抢走（只有不带修饰键的 n 才是我们的）。
- SPA 翻 20 个视频不再攒 20 组匿名监听器。
- toast 挂进全屏播放器里，全屏按 Note 屏幕有反应了。
- 内联 `ytInitialPlayerResponse` 的解析器不再用 `indexOf(";")` 截 JSON（分号在字符串里必然失败）。
- 面板的 relay 现在指名道姓地问自己的那个标签页，不再抓后台任意一个 YouTube 标签页。

**后端**（`server/`）

- `DATABASE_URL` 缺失时不再悄悄用每实例一份的内存库（所有人被登出、笔记消失、没有一个错提到数据库）。
- 连接串不再进日志：抛错的位置挪到了 try 之外的地方，错误只带 `{name, code}`。
- 在第二台设备上重新收藏一个词，不再抹掉它的翻译、讲解和「已掌握」。
- 删掉的笔记不会从服务器回来（墓碑），它的复习进度也留着。
- 超过 2670 字节的生词句子不再被唯一索引拒绝（身份改成两个 md5 拼起来的哈希列）。
- 每个账号的行数有上限，delta 有 LIMIT，导出有 8MB 上限：一个账号拖不垮整个 Worker。
- 会话真的绑在浏览器上了：登录带上设备名，JWT 里有设备声明，每次带 token 的请求都带设备名。
  README 里那句承诺现在是真的。
- 部署文档改成「先上 secret 再 deploy」。

**门**

- CI 第一次真的跑变异测试（96 条 → 现在 7 个脚本，每条都要被抓到）。
- prompt 的占位符现在有测试断言真的被填了。
- `check-prompts.js` 的小节正则不再只认两个字面量。
- `release.test.js` 保护的是行为，不再是源码正则。
- i18n 覆盖检查扫的是文案表，不是整个源文件。
- OAuth 的 nonce 守卫和笔记串行化锁删掉之后，测试会红。

### 5.3 这一轮自己也长出来的两条

审计员报的是他们看见的东西。这一轮修的时候，又有两个问题是从修复里长出来的，
不修的话它们会留在树上：

1. **变异脚本会写坏正在被编辑的文件。** 脚本改源码、跑测试、再还原。
   五个队并行改代码的时候，一个队正在改 `sidepanel.js`，另一个队的变异脚本刚好在还原
   `sidepanel.js`——那份改动就没了。现在变异脚本有信号处理，被杀掉也会把文件放回去。
2. **门自己也会说谎。** 视觉门用「按钮里有几个文本节点」来判断「标签是不是折了行」，
   而标签一旦由几段组成（标题 + 分隔符 + 时间戳药丸）就会被误判成三行。
   门改成数「文字落在几条横线上」。改完以后先验证它还抓得住真的折行——抓不住的门不是门。

  开发者账号、支持邮箱、商店名称三件事还空着。这三件事要人来定。
- **网页控制台（`server/dashboard/`）这一轮没有人审。** 它是产品的一部分，
  五轮下来它一直在审计范围之外。下一轮第一个要看它。

  这一轮的门全都在测「已经知道要做什么的人」。

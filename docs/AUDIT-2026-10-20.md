基线提交：`a22cbbf`（v1.4.0）

---

## 零、这一轮的做法

这一轮不是"扫一遍代码报个 bug 列表"，而是三段闭环：

1. **分组审查**：四个互不重叠的专家组并行审（扩展运行时 / 后端安全 / 文档与信任 / 视觉与可访问性），每个组只报自己那一片，避免重复和互相污染。
2. **负责人复核**：**每一条 P0/P1 在派单修复之前都由我独立复核过**，复核方式是读源码 + 实际执行（跑脚本算对比度、跑 `Number(null)`、跑 `atob` 抛错、跑变异测试看测试是否真的会红）。上一轮项目审查留下的两条"误报"就是这么来的——所以这一轮的结论全部是可执行的。
3. **变异测试验收**：修复合进来之后，**逐个把修复点破坏掉**，看测试会不会变红。测试不会红的修复不算修复。已执行的变异全部记录在第五节。

> 教训记录：变异测试本身也会骗人。我做过一次"变异"，只加了一行注释却没删掉原来的修复代码，测试自然全绿——那不是"测试没覆盖"，是我自己没变异到位。读源码复核后发现，改成真正删除修复行后测试立刻变红。**先确认变异真的生效，再相信结论。**

## 一、扩展运行时（sidepanel.js / background.js / content.js）

### P0-1　分析失败时用户看到的是错误码，不是人话

- **位置**：`sidepanel.js:1703`（修复前）
- **问题**：`analysisResult.error` 被直接塞进 DOM，用户看到的是 `NO_AI_KEY` 这种内部代号。
- **后果**：AI 密钥没配，最需要引导用户去设置页的时刻，界面给的是一串错误码。
- **修复**：改用 provider 返回的 `message`；`NO_AI_KEY` 时额外渲染一个真实的「Open Settings」按钮。
- **验收**：变异测试——把 `message` 改回 `error`，测试 `an analysis failure shows the provider message, never the error code` 变红 ✅

### P0-2　只有 Supadata 密钥才能启动面板，AI 密钥却也拦路

- **位置**：`sidepanel.js:264`
- **问题**：启动时同时要求两个密钥。但 AI 密钥只有 Overview 标签才需要，Transcript 标签完全不用。
- **后果**：只想读字幕的用户被一个用不上的密钥卡在死路上。
- **修复**：只有 Supadata 密钥参与启动判断；AI 密钥改为惰性校验，缺密钥时在 Overview 标签就地说明。同时新增 `chrome.storage.onChanged` 监听——用户在设置页补上密钥后面板自己活过来，不需要重开。
- **验收**：变异测试——把 AI 密钥条件加回去，两个测试变红 ✅

### P0-3　服务坏了，被说成"你少配了 API 密钥"

- **位置**：`sidepanel.js:277` 附近
- **问题**：`chrome.runtime.sendMessage` 失败时，catch 分支把任何失败都渲染成"缺少 API 密钥"。
- **后果**：扩展自身故障（service worker 挂了、存储区异常）被伪装成用户的配置问题，用户会反复检查自己的密钥。
- **修复**：区分"扩展故障"和"缺密钥"两种状态，前者有独立的标题和文案。

### P0-4　慢响应会串到下一个视频

- **位置**：`sidepanel.js:1674-1721`（`triggerAnalysis` 无 videoId 守卫）
- **问题**：用户点开视频 A，字幕很慢；中途切到视频 B；A 的响应回来后被渲染到 B 上，并且**以 B 的 videoId 写进缓存**。
- **后果**：界面上是 B 的字幕配 A 的概览，缓存被污染，且没有视频 ID 的键，用户再也看不到正确的 A。
- **修复**：引入 `digestGeneration` 票据。每次 digest 运行开一张票，所有 `await` 之后校验票据与 videoId，不匹配就丢弃。
- **验收**：变异测试——去掉票据校验，`a slow transcript for the previous video never lands on the new one` 与 `a slow analysis for the previous video never lands on the new one` 双双变红 ✅

### P0-5　一次失败的界面翻译，终身不可用

- **位置**：`sidepanel.js:2821`（`interfaceTranslationFailures.clear()` 的唯一调用点）
- **问题**：失败集合是"拒绝名单"，只在切换模式时清空一次。一个段落翻译超时，这一整章在面板生命周期内就再也翻不了。
- **修复**：切换视频和切换模式都清空；失败的段落渲染一个 Retry 按钮（用捕获阶段委托监听，避免和"点击章节跳转视频"打架）。
- **验收**：变异测试——去掉视频切换时的清理，`changing video clears the failed interface translations` 变红 ✅

### P1-1　每次打开面板都跑一次全量词汇同步

- **位置**：`sidepanel.js:277-279`
- **问题**：面板一开就触发 `syncVocabulary`，而扩展里根本没有词汇界面。
- **后果**：每次开面板都产生一次无用的网络往返 + 服务端负载。
- **修复**：移除该调用。

### P1-2　分析进行中标志会永久卡死

- **位置**：`sidepanel.js`（`isAnalysisLoading` 手动置位/复位）
- **问题**：异常路径不复位，Overview 标签此后完全失灵。
- **修复**：改用 `finally` 释放。
- **验收**：**这一条最初没有测试守护**——变异测试显示去掉 `finally` 里的复位，136 个测试依然全绿。补测试后变红 ✅（详见第五节）

### P1-3　错误码没有分级文案

- **位置**：`sidepanel.js`
- **问题**：`NO_SUPADATA_KEY` / `INVALID_SUPADATA_KEY` / `RATE_LIMITED` / `NO_TRANSCRIPT` / `EMPTY_TRANSCRIPT` / `OUT_OF_CREDITS` 全部走同一条兜底文案。
- **后果**："密钥无效"被说成"没找到字幕"，用户去视频里找根本不存在的字幕。
- **修复**：逐个错误码配标题、说明和可执行的出口（补密钥 / 充值 / 等待）。

### P1-4　笔记清理只认 DeepSeek 的密钥

- **位置**：`background.js:1469`
- **问题**：`if (!settings.aiApiKey)` 只检查 DeepSeek 字段。
- **后果**：用 MiniMax 或 OpenCode Go 的用户，笔记清理功能静默失效。
- **修复**：改用 provider 注册表派生的 `getActiveAiKey(settings)`。
- **验收**：变异测试——改回 `settings.aiApiKey`，`the note cleanup uses the key of the active provider` 变红 ✅

### P1-5　Supadata 返回 402 时不告诉用户是额度用完了

- **位置**：`background.js`
- **修复**：402 映射为 `OUT_OF_CREDITS`，面板给出充值指引。

### P2-1　Panel 内置 UI 零 i18n

- **位置**：`sidepanel.html`（`data-i18n` 属性数量 = **0**）
- **问题**：设置页有中英双语，面板全是硬编码英文。用户选了中文，面板还是英文。
- **修复**：新增 `PANEL_COPY` 覆盖表（en / zh-CN），覆盖状态页、空态、错误文案。

### P2-2　花钱之前不说花谁的钱

- **问题**：字幕查询消耗 Supadata 额度、AI 概览消耗自己的 AI 余额，界面上零提示。
- **修复**：头部一行成本披露；生成概览时明确说明"会消耗你的 AI 额度"。

### P2-3　`keyMoments` 是一个从不存在的能力

- **位置**：prompt / `background.js` / 面板 / 内容脚本
- **问题**：`content.js:752-755` 的 `highlightKeyMoments` 是一句 `return;`，整条链路是死的，但 prompt 里还在要求模型产出 `keyMoments`——**每次分析都在为不存在的输出付费**。
- **修复**：从 prompt、后台、面板、内容脚本整条删除。

### P3-1　笔记筛选不记忆

- **问题**：面板文档每次打开都是新的，"All Notes"选择永远重置回"This Video"。
- **修复**：筛选偏好存 `ytd_notes_filter`。

### P3-2　笔记 ID 会撞

- **位置**：`background.js:1297` / `:1427`（`note_${Date.now()}`）
- **问题**：同一毫秒内保存两条笔记会生成相同 ID。

## 二、后端（Cloudflare Worker / Neon）

后端这一组全部由独立分组审查 + 变异测试双重把关，测试数从 42 涨到 77。

### P0-1　`parseReviewGrade` 把 `null` 当成 0 分

- **位置**：`server/src/validate.js:70-75`
- **问题**：`Number(null) === 0`，`{grade: null}` 通过校验被当成"完全不会"。
- **修复**：先排除 `null` / `undefined` / 布尔 / 空白字符串，再做类型强制。
- **验收**：变异测试——把路由里的 grade 校验去掉，`a JSON review body with an invalid grade names the grade, not the body` 变红 ✅
- **备注**：只删 `validate.js` 里的空值检查时测试**没有**变红——因为函数里还有第二道 `typeof value !== "number"` 拦着。**这是冗余保护，不是测试缺口**；我改成在路由层变异才命中。这条是本轮第二次"变异测试骗我"，处理方式和上一条一样：读源码确认，再改正确的变异点。

### P0-2　JWT 签名解码在 try/catch 之外

- **位置**：`server/src/jwt.js:68-70`
- **问题**：签名格式非法时抛的是通用异常，返回 500 而不是"会话过期"的 401。
- **修复**：移进 try/catch。
- **验收**：变异测试——把解码移出 try，`a malformed JWT signature is an expired session, not a server error` 变红 ✅

### P0-3　`updateNote` 会把 `clientId` 改写成客户端传来的值

- **位置**：`server/src/db.js:120-129`（MemoryStore）vs `:394-411`（NeonStore）
- **问题**：MemoryStore 会改写，NeonStore 不会——两边行为不一致，且允许客户端伪造归属。
- **修复**：MemoryStore 改为 `delete next.clientId` 后再赋值。
- **验收**：变异测试——删掉 `delete next.clientId;`，`[MemoryStore] updateNote never rewrites the client id` 变红 ✅

### P0-4　请求体大小无上限

- **位置**：`server/src/middleware.js`
- **修复**：`MAX_BODY_BYTES = 128 * 1024`，超出返回 413。

### P0-5　接口无速率限制

## 七、下一轮要解决的（第一轮审查之外的存量问题）

第一轮修的是"会出错、会误导、不可信"的问题。下一轮处理**产品能力缺口**：

1. **资料库 / 历史记录缺失**——最大的产品缺口。摘要被缓存了，但用户没有任何入口能看到过去的摘要，缓存还会在 20/30 天后静默淘汰。
2. **词汇功能三端错配**——扩展无入口、后端在存、每次开面板还在同步。这是最坏的中间状态，需要产品决策：**接回 UI**（新增 Words 标签 + 划词捕获 + 复习）或**彻底砍掉**。
3. **同步冲突依赖设备时钟**——`cloud-sync.js` 用 `new Date(cloud.updatedAt)` 对比本地时间戳，设备时间不准就会静默回滚或丢失用户编辑。
4. **Explain 弹窗无 `role="dialog"`、无焦点陷阱、Esc 不关闭**。
5. **翻译没有进度、没有取消**。
6. **面板里没有"记笔记"入口**——必须把鼠标移到视频上。
7. **面板没有收藏/星标，也没有 Dashboard 入口**。
8. **内容脚本注入的按钮与新设计系统脱节**。
9. **`sidepanel.js` 3157 行 / `background.js` 1907 行**，需要模块拆分。

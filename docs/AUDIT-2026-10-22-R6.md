# 第六轮：把它交给一个不认识它的人

日期：2026-10-22
基线提交：`4a494ff`（本轮开始时的 `main`）
分支：`main`

> 前五轮是「在自己的产品里找问题并修」。这一轮换了三个问题：
>
> 一、**这个东西能不能交给一个不认识它的人？**——商店页面、包、文档，都是产品的一部分。
> 二、**它对自己用户的数据说的是不是真话？**——「删了」「同步了」「导出了」，说出口的话要算数。
> 三、**它在一个大账号、一支长视频上是不是还站得住？**——上一轮修的是「一个人用」。
>
> 做法还是老一套：找人来当自己的眼睛，每一条都带证据，然后逐条自查、修完再审。
> 这一轮多了一条：**发布物也算产品**。商店的五张截图以前是手工拼的，包是某一天打的，
> 文档是在功能还没定下来的时候写的——它们都比产品旧，而商店会把它们当成本产品给用户看。

---

## 零、这一轮的做法

1. **五个角度同时进场**，互相不知道对方在做什么。角度不是「按文件分」，是「按人会怎么用它分」。
2. **每一条都带证据**：文件行号 + 用户看到的症状 + 怎么确认的。没有证据的不算缺陷。
3. **先自查再动手**：审计报告是别人的结论，不是事实。复现不了的不改。
4. **改了就要有门**：每一条修复都配一个「改了会红、还原会绿」的测试。
   仓库的规矩是 **"a gate that cannot fail is not a gate"**。
5. **分队不重叠文件**：每个队只拥有自己的文件，避免并行写坏同一处。
6. **门要证明自己会失败**：这一轮新加的门，先证明它抓得住真的错，再让它长期守在那里。

本轮一共收到 **72 条**结论（五个角度合并去重后）。裁决如下：

| 裁决 | 条数 | 含义 |
| --- | --- | --- |
| 修 | 68 | 复现了，是真缺陷 |
| 有意不改 | 2 | 是真缺陷，但今天不改：改了会让页面说假话，理由写在下面 |
| 要人来定 | 2 | 需要一个人做决定，或者需要一次对外的发布 |

## 三、已修掉的

### 3.1 商店与发布物

- **五张商店截图现在是从产品上拍的**：`scripts/panel-review.js --store` 把面板按
  450×780、2 倍像素密度拍成 900×1560（和演示图里侧边栏那一栏的宽度一样，是量出来的），
  `scripts/store-shots.js` 把它贴进演示图，整幅缩到商店要的 1280×800。
- **`node scripts/store-shots.js --check` 会重拍一遍跟仓库里的比**：不一样就打印
  「The listing is not the product any more」并退出 1。这个门是证明过会失败的
  （把一张图改坏，它确实抓出来了）。
- **包要自证来源**：`scripts/verify-package.js` 把 ZIP 里的每个文件和仓库里的那一份
  逐个对一遍（SHA-256），对不上打包就失败。CI 的第四个 job 也做同一件事。
- **现在的包**：`dist/youtube-digest-v1.8.0.zip`，27 个文件，SHA-256 以
  `npm run package` 当次输出为准（不要抄旧记录）。打包脚本会点名这个是唯一该上传的，
  其余旧包会被列成「not for upload」。

### 3.2 面板

- 字幕行的时间戳穿上了和其他地方一样的 chip（浏览器默认的 `2px outset` 边框没有了）。
- 缺 Key 的时候按「总结」不再自己花掉额度，而是打开一个对话框把人带去设置页。
- 面板不等账号：先打开，后台同步在后面进行。
- 三小时的视频不再一次画出三千行：一次画一屏，其余是预留的位置，不是造出来的行。
- 搜索等输入停稳再跑，它会找屏幕上还没有的那个词，标记要截断时说清楚一共有多少。
- **面板不再把 worker 自己写的那句话给用户看**：`NO_TRANSCRIPT` 这条分支曾经是
  唯一一个例外，现在它和其他失败一样用面板自己的句子；连面板不认识的代码也是——
  那种情况下用的是通用句，而不是 worker 的原话。

### 3.3 数据与账号

- 退出登录会把这台浏览器上的副本一起带走，并且**先问一句**。
- 删除账号会连待删队列一起清掉；「删除全部笔记」真的删掉，删不掉的时候会说。
- 第一次登录会报告移了多少条笔记和多少个生词过去。
- 墓碑行不再被同步接口返回，被删掉的笔记不会回来。
- 增量同步带上 `truncated`，被截断的方向说清楚。

### 3.4 网页控制台

19 条全部落地，配了 **33 个浏览器门**（`server/dashboard/checks/dashboard-gates.mjs`），
每一个都在真实 Chrome 里量过：320/360/375/414 四个宽度的横向溢出、会话过期时
说的那一句话和收令牌的顺序、中文页面上的英文报错、按钮的可访问名称、复制和删除
不再长得一样、状态选择框有名字、登出后 DOM 里不再留笔记、隐私政策在未登录时
也点得到、nonce 在点击之前就写进链接、切标签不再重取笔记、静态资源带齐四个安全头。

### 3.5 文档

`PRIVACY.md` / `PRIVACY.zh-CN.md` / 两份 README / 安装指南 / 商店材料包 /
安全说明，按**代码实际在做什么**重写了一遍。改掉的说法是那些不对的：

- 面板里写的笔记是原样保存的，AI 永远收不到它；只有视频页上的 Note 按钮会去整理字幕；
- 退出登录停止镜像，并清掉这台浏览器上的副本；服务端的账号留着它已有的东西；
- 删除账号和删除全部笔记是两件事，两件都说出口；
- 浏览器名字不进数据库，它只跟着那一次会话；
- 一个账号最多两万条笔记和生词，满了服务端会说出来；
- 凭据扫描读的是仓库里的每一个文件，安全说明写明它仍然看不见的地方。

## 四、这一轮定下的规矩

1. **发布物也是产品。** 商店上的每一张图、商店里写的每一句话、给出去的每一个包，
   都是产品的一部分，都要和代码一起被检查。
2. **截图不能是手工拼的。** 手工拼的截图是某一个产品的照片，产品一改它就是历史。
   现在截图是拍出来的，而且有门证明它没有过期。
3. **包要自证来源。** 「这个 zip 是这次代码打出来的」这句话不该靠人记得，
   打包脚本每次都自己证明一遍。
4. **文档里的每句话都要有代码撑着。** 文档和代码不一致的时候，改文档；如果代码
   承诺的东西它做不到，改代码。
5. **门要证明自己会失败。** 本轮有一条变异「活下来了」——不是门坏了，是它保护的
   承诺变了（面板现在在两处守住同一句话，那条变异只在其中一处破坏了它）。
   正确的做法是把变异改到新的那处，而不是把门放松。
6. **变异脚本在副本上工作。** 它改源码、跑测试、再还原；在工作树里做这件事，
   会把另一个队正在改的代码一起还原掉。本轮改成先复制到临时目录再动手，
   工作树只被读。

## 六、这一轮没有解决的

- **上架本身没有做。** 三件事要人来定：Chrome Web Store 开发者账号（$5）、
  一个有人看的支持邮箱、商店名称里的 `YouTube` 商标风险（被打回时的备用名已经写好）。
  上架那天还有两处文字要改（README 里「不在商店上架」那句，和商店描述里的
  「local install」），`docs/WEB_STORE.md` 里逐条列了。

  线上 `https://ytd.panbo.space/privacy` 还是旧的。这需要一次 Worker 部署，
  是一次对外的发布，所以这一轮没有动。

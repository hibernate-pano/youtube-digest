## 零、这一轮的做法

第二轮修完的是「会出错、会误导」的问题。第三轮面对的是**已经能用的产品**，
所以这轮的问题不再是「功能坏了」，而是：

1. **产品会不会说话。** 功能做出来了，但成功和失败都只写在开发者看得见的
   地方——错误码、console、aria-live 区域。视力正常的用户看到的是一个
   「什么都没发生」的界面。
2. **产品认不认得用它的另一种人。** 面板是照着「人坐在电脑前用鼠标」写的。
   纯键盘的用户、少动效的用户、只看英文/中文的人，都是后来者。
3. **产品在极端条件下会不会说谎。** 请求挂住、存储写满、网络断掉——这些
   时候界面给不出答案，甚至给出错误的答案。
4. **登录是不是一把别人账号的钥匙。** 这是第二轮遗留的最后一块安全债务。

和前两轮一样：每一条关键修复都要有一个**变异**能让它变红，否则不算修好。
这一轮一共跑了 **13 个变异，全部被抓住**。

## 一、失败：用户看不见发生了什么

### P0-A　面板的失败只有读屏用户能听见

**事实**：`sidepanel.js` 里有 26 处播报，全部写进视觉隐藏的 live region。
屏幕阅读器用户会听到「出错了」，视力正常的用户看到的是**什么都没发生**。

- 存笔记失败：按钮上的字变成「Error」，1.5 秒后变回原样。
- 摘要失败：章节区里出现一行红色的错误码（例如 `NO_AI_KEY`）。
- 翻译失败：面板上没有任何东西改变。

**为什么这是 P0**：这不是「体验不好」，这是**产品在撒谎**。用户点了保存，
系统说保存了（按钮变回原样），但东西没存。用户没有理由怀疑自己。

**已修**（`e392f63`）：面板底部出现一条**可见的提示条**（`#panelToast`）。

- 状态类消息几秒后自己消失；错误类**留住**，并且用错误色。
- 提示条是 `fixed` 的，不吃点击事件，也不撑动布局；浮动的「跟随播放」按钮在
  提示出现时让开。
- 屏幕阅读器仍然读隐藏区域，两边不重复。
- 已经显示在屏幕上的状态（加载页、空状态、错误页）不再重复播报一遍。

### P0-B　错误码直接糊在界面上

`background.js` 的失败码是写给开发者看的（`NO_AI_KEY`、`AI_IDLE_TIMEOUT`、
`SYNC_SESSION_EXPIRED`……），它们**原样**出现在摘要区里。

**已修**：12 个错误码各有一句中英文的话；供应商自己的报错原样保留（那是唯一
能解释供应商失败的信息）；未知的码退回到通用句子，而不是把
`SOMETHING_ELSE` 摆到用户脸上。

**这一轮又补了 3 个**（`SYNC_REQUEST_TIMEOUT` / `TRANSCRIPT_REQUEST_TIMEOUT` /
`STORAGE_QUOTA_EXCEEDED`，见第三、四节），现在是 15 个。

### P0-C　界面里混着硬编码的英文

`Copied`、`Retrying…`、`Translation failed.`、`No matches`、工具条上的
`Explain` / `Note` / `Word`、`Untitled video`——这些句子在中文界面里也是英文。

**已修**：全部进入复制表，中文界面里一个英文残留都没有（新增守卫）。

### P1-D　资料库的空状态和搜索无结果，是同一句话

原来的三元表达式是死的，两种情况返回同一句「还没有条目」。用户在搜索框里
输了错的东西，被告知「你还没有条目」——**界面在否认用户刚刚做过的事**。

**已修**：拆成两句。相对时间也从 `3 d` 改成「刚刚 / N 分钟前 / N 天前」，
中文界面不再显示英文缩写。

### P1-E　复习排在 500 个生词的下面

复习是有时间性、要动手的部分，却排在整个生词表下面。**已修**：复习区移到
生词表上面，DOM 顺序和键盘顺序一起跟着走——面板的第一个可聚焦控件现在是
复习卡。

## 二、键盘与动效：只按「人坐在电脑前用鼠标」写的

### P0-F　纯键盘的用户永远等不到那排按钮

选中字幕文字后出现的「解释 / 笔记 / 生词」工具条只挂在 `mouseup` 上。
用 `Shift + 方向键` 选字的纯键盘用户，**等一辈子**也等不到它。

**已修**（`664e229`）：加了 `keyup` 这条路——键盘松开选字键的瞬间弹出工具条
并把焦点送进去；`Esc` 关掉工具条，焦点回到转录原文和原来的选区。鼠标那条路
一行没动。转录区也加了自己的落点，键盘有地方停，关掉工具条后不会「掉」回
面板顶端。

### P0-G　弹窗的 `aria-modal` 是假话

生词弹窗写着 `role="dialog"` 和 `aria-modal="true"`，但 `Tab` 一下就跑到弹窗
背后去——`aria-modal` 承诺的「焦点被圈住」根本没实现。关掉弹窗之后焦点也不
知道还给谁，键盘用户直接落空。

**已修**：`Tab` / `Shift+Tab` 在弹窗里循环，`Esc` 关闭，焦点还给打开它的按钮，
弹窗背后的面板同时变成 `inert`（读屏和键盘都碰不到它）。解释弹窗本来就有焦
点圈，改用同一套 helper，两处行为一致。

### P1-H　「减少动效」的设置在面板里没人听

系统设置里的「减少动效」在面板里完全无效：动画和过渡照跑。

**已修**：`sidepanel.css` 和 `options.css` 都加了 `prefers-reduced-motion` 的块，
把动画和过渡压到 `0.01ms` 再跑一次，元素落在动画的**最后一个**状态（不是冻在
开头的隐形状态）；加载条的高光单独改成铺满整条，滚动也改成不跟随。

逐条看过项目里的动画：唯一的 keyframes 是加载条的高光和淡入淡出，`fill-mode`
没有一个写 `forwards`，所以压短动画不会留下看不见的元素。

## 三、登录：token 是一把别人账号的钥匙

### P0-I　一条带 token 的链接 = 你的账号被别人看

以前只要页面上出现 `#access_token=...`，客户端就把它收下来当成登录凭证。

具体的坏处不是「token 泄露」这么笼统，而是：

- 用户点开一条链接（聊天里的、邮件里的、网页里的），面板就悄悄切到了**另
  一个账号**；
- 切过去之后，那个账号在本机的笔记、单词、复习进度**跟着显示出来了**——别人
  账号的内容出现在自己屏幕上；
- 界面上没有任何提示：用户以为自己在看自己的笔记。

登录时用的 `state` 挡不住这个：`state` 保护的是**发起登录的那个请求**不被
别人伪造，但 token 落地之后就被复制走了，和 `state` 无关。

**已修**（`dc29a3e`，`ADR-005`）：服务端把客户端给的随机 nonce 原样带在 token
后面回来；客户端**两个都要对**——token 拿走，nonce 拿去和本机存的那份比，对不
上（包括根本没有 nonce）就整条丢弃，不写进任何存储。

顺带把这条回程上的其它洞也补了：

- 状态 cookie 换成 `__Host-` 前缀（兄弟子域写不坏它），并且用过一次就作废
  ——**换 token 失败时同样作废**，不然同一个 `state` 能被重放。
- 回调接口加了频率限制。它是公开的，不然谁都能拿这个服务去砸 GitHub 的
  token 接口。

**代价（有意接受）**：没有 nonce 的 token 一律被拒。宁可让用户重新点一次登
录，也不能把账号交给别人。代价是「从旧版本复制过来的登录链接」会失效一次。

### P1-J　同步服务打了个 500，用户就被登出了

`fetchGithubProfile` 对任何非 2xx 响应都返回 `null`，而 `null` 的意思是「登
录已过期」。服务抖一下，用户的会话就没了。

**已修**：只有 `401` 才算会话过期。`500` 会被说成「同步服务出了点问题」，
会话留着。这一条有两条测试守着，其中一条专门验证「服务在闹脾气时用户不会被
登出」。

### P1-K　面板上那个「重试」按钮按了也没用

登录失败时，面板上出现一个「重试」按钮，点它会**原样再失败一次**——没有
cookie 就没有会话状态，重试改变不了任何事。

**已修**：去掉这个按钮。而且要保证它**不复活**——原来切换界面语言会用新的
文案重画状态行，顺手把「重试」按钮也画了回来。修法是把这个决定记在状态里
（`statusState.noRetry`），切换语言时带着一起重画。

### P1-L　扩展里没有「删除我的账号」

隐私政策写着用户可以删除自己的数据，但扩展里做不到——只能去网页控制台删，
而那里要先登录 GitHub。

**已修**（`ef62fd0`）：设置页里加了「删除我的账号」，两次确认之后：

1. 调 `DELETE /api/account`；
2. 只删这个账号自己的本机数据（`ytd_notes_<githubId>` 等），不动别的账号；
3. 结束会话。

**并且用真的 Postgres 证明过**（`da88961`）：`users` / `notes` /
`vocabulary` / `review_items` 四张表的行都没了，这个账号的 token 也立刻失效。

**修的过程中发现的一个真 bug**：正在飞行的资料刷新会把刚删掉的会话又写回
去。加了会话互斥锁（`withSessionLock`），并且在锁里面**再检查一次**会话还在
不在。第一版测试没抓住它——因为 mock 太快，刷新先返回了。测试重写成把
`/api/me` 的响应挂在闸门后面，删除先跑，闸门后开，变异才被抓住。

## 四、运行时韧性：请求会挂死，存储会写满

这一节是这一轮**最接近「产品会不会撒谎」**的部分。三个场景，界面原来都
给不出答案。

### P1-M　Supadata 挂住 = 面板永远转圈

字幕请求没有截止时间。服务端不回答，MV3 的 service worker 在等待时被挂起，
面板就停在那儿。用户在转圈，credits 在烧（或不烧，但谁知道）。

**已修**（`background.js` + `settings.js`）：请求跑在一个截止时间下（45 秒），
超时被翻译成 `TRANSCRIPT_REQUEST_TIMEOUT`。截止时间被强制了**两次**——有
`AbortController` 就用它取消，没有也照样让 Promise 落败，所以调用方一定拿
得到答案。

同样的处理给了同步服务（20 秒，`SYNC_REQUEST_TIMEOUT`）。

**并且**：一个超时**不是**一个死会话。代码把两者分开，面板永远不会因为服务
端慢就把用户赶去登录页。

### P1-N　存储写满 = 笔记静默消失

`chrome.storage.local` 默认只有 **10MB**。而扩展缓存的每个视频都带着字幕、
译文和摘要，面板一次保留 20 个视频。

实测（用面板真实的缓存结构合成字幕测量）：

```
30 分钟的视频：每个 0.09 MB -> 20 个 = 1.8 MB
2 小时的视频：  每个 0.37 MB -> 20 个 = 7.3 MB
4 小时的视频：  每个 0.74 MB -> 20 个 = 14.8 MB   <-- 超过 10MB
```

真实字幕比合成的长，再加笔记、词汇和生词，越过 10MB 只是时间问题。

写满的时候，旧代码把异常吞掉：界面显示保存成功，**东西没存**。

**已修**（三层）：

1. **`unlimitedStorage` 权限**——把上限从 10MB 提到无限制。这是根因上的修
   补，权限的理由写进了商店材料。
2. **写满时先扔缓存**——缓存是唯一还能再取回来的东西，笔记和生词不是。写
   失败时按「最旧 → 过期」扔掉缓存，腾出空间重试一次。扔掉的视频会被记下
   来，资料库会**明确告诉用户**「为了腾地方，扔掉了 N 个缓存视频」。
3. **实在存不下就说人话**——`STORAGE_QUOTA_EXCEEDED` 有一句中英文的话。

**这一轮我自己补了面板这一侧**：面板自己写 `digest_*` 缓存那条路**没有**走
上面的恢复逻辑，写满时依然只是 `console.error`。现在它会先扔掉一半缓存重试，
还不行就全扔，最后在屏幕上说一句话（「这台设备的存储空间已满，这个视频没有被
缓存」）。**注意**：这和「用户存的笔记被扔掉」是两回事，界面必须把这两种说
清楚。

### P1-O　登录时把别的账号的笔记删掉了

这是一个**数据丢失**级别的缺陷，而且不容易发现。

未登录时存的笔记放在一个公共桶里（`ytd_notes`）。登录时，这个桶会被「导入」
到新账号的桶里，然后**整个桶被删掉**。问题在于：那个桶里可能有**上一个账
号**留下的笔记——它们没有被导入（因为归属标记说它们属于别人），却跟着桶一起
被删了。**上一个账号的笔记在这次登录时消失了。**

旧代码的顺序是：导入 → **删掉整个桶** → 再写归属标记。

**已修**（`cloud-sync.js`）：顺序反过来了，而且只删真正搬走的那部分。

1. **先写归属标记**（claim）。没被认领的条目可能被下一个登录的账号捡走，
   所以归属先落盘。归属写不进去，**就一步都不动**——东西留在原处，下次登
   录还能找到。
2. **再拷贝**（copy）。按 id 合并，所以跑两遍也不会多出东西。
3. **最后只清理搬走的**（delete）。属于别的账号的条目留在原地。

每一步被打断，条目都留在一个还找得到的地方，而且**不会同时属于两个账号**。

笔记和生词走同一条路，所以把两段几乎一样的代码收成了一个 `migrateLegacyBucket`。

## 五、文档与上架

### P1-P　隐私政策少说了同步服务实际存了什么

**已修**（`PRIVACY.md` / `PRIVACY.zh-CN.md`）：写清楚同步服务存什么、存多久、
谁能看、怎么删。两份语言政策对齐，中文那份是**便利译本**，英文那份是**准**。

### P1-Q　商店材料里的权限声明是旧的

`docs/WEB_STORE.md` 写着「权限声明：sidePanel、storage、tabs、scripting」，
而这一轮加了 `unlimitedStorage`。**权限声明和实际 manifest 对不上，是上架被拒
的常见原因**，也是让用户不信任的理由。

**已修**：声明改成和 manifest 一致，并说明为什么需要它（10MB 的默认上限装不
下一个长视频的字幕和译文；数据仍然只在这台设备上，不外传）。

### P1-R　CSP 和 Cloudflare 的统计脚本打起来了

面板的响应头里有一条严格的 CSP（`script-src 'self'`），Cloudflare 注入的
统计脚本被它挡掉了，浏览器控制台每次都报两条错。

**决定**：**保留 CSP，不为了统计放宽它，也不去动 zone 上的设置**（`ADR-006`）。

1. CSP 是这个产品对用户许下的承诺，不是配置项。隐私政策里「不发送任何分析
   统计」这句话，因为统计脚本从来没被放行过，在**事实上**成立。
2. 统计不是这个产品要做的事。
3. `panbo.space` 上还有博客、教练页、其它面板等七八个站点。关掉 zone 级的
   Web Analytics 会影响它们——那不是这个项目能替别人做的决定。

**代价**：控制台里有两条报错。它们是 CSP 在**工作**的证据，不是故障。

## 七、下一轮要解决的

- **面板的存储自愈还差一层**：面板现在会自己腾地方，但它腾的只是**自己写的
  缓存**。后台写的笔记、生词走的是另一条路（`cloud-sync.js` 的
  `setStorageWithRecovery`）。两条路的回收策略不同——后台那条只扔缓存，面板
  这条会扔到一半再全扔。要统一成一条。
- **账号删除的前端还没有全流程测试**：后端用真 Postgres 证过，扩展里点按钮
  的那条路目前只有 mock 级别的测试。
- **资料库该有「导出」**：数据能导出 Markdown 了，但笔记和生词分开导出，没
  有一份「打包带走」的入口。
- **面板还没有键盘快捷键说明**：键盘路径已经全通，但用户不知道有这回事。
- **上架材料里的截图还是 v1.4.0 的界面**：五个标签页、上传状态这些都变了。

## 八、这一轮的方法论（留给下一个接手的人）

这一轮和前两轮有一个**根本不同**：前两轮修的是「产品坏了」，这一轮修的是
「产品不会说话」。

这带来一条新的验收标准：

> **一个失败，如果用户看不见，它就还没有被修。**

这条标准在代码里长这样：

1. 界面上的每一句失败都要有一句**人话**（中英文各一份），不能是错误码。
2. 每一个**写操作**的失败都要有一句人话——存笔记、存生词、存缓存、登录、
   同步，一个都不能少。
3. 错误码是给开发者的，**不许**直接摆到界面上；供应商自己的报错可以原样保
   留，因为那是唯一能解释供应商失败的信息。

以及另一条从这一轮学到的：

> **一个测试如果不需要 mock 帮忙，就别用 mock 帮忙。**

「删账号后刷新把会话写回来」这个 bug，第一版测试因为 mock 返回太快而**没抓
住**。真实的时序里，刷新就是在删除之后才回来。测试必须把 mock 调成**现实
的样子**，否则它守的是一个不存在的世界。

**下一轮请继续用同一把尺子。** 不要接受「测试全绿」作为「产品是对的」的证
据，也不要接受「日志里有错误」作为「用户知道出了事」的证据。

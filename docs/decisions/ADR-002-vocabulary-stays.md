# ADR-002: 词汇与复习功能接回界面，不砍掉

## Status
Accepted（2026-10-20）

## Background

第二轮审查发现词汇功能处于三端错配的状态：

| 端 | 状态 |
|---|---|
| 后端（`server/src/routes/vocabulary.js`、`reviews.js` + 两张表） | 完整、生产可用、刚被修好并补了契约测试 |
| 扩展侧同步层（`cloud-sync.js` 的 `fullSyncVocabulary`、`handleSaveVocabulary`、`handleGetVocabulary`、`handleDeleteVocabulary`、`handleGetDueReviews`、`handleSubmitReview`） | 完整、可用 |
| 扩展界面 | **没有入口**。面板里没有词汇标签，也没有划词捕获 |
| Dashboard（`server/dashboard/index.html`） | **只读**——能展示词汇和复习，但没有词汇产生 |

第一轮已经修掉了一个坏味道：面板每次打开都发一次 `syncVocabulary`（`sidepanel.js` 启动路径），而扩展根本没有词汇界面。那是无用的网络往返和服务端负载。

剩下的选择只有两个：**接回 UI**，或者**彻底砍掉**。

## Decision

**接回 UI。**

理由，按权重排序：

1. **砍掉是净损失，不是节省。** 要删 7 个文件、改 4 份文档、毁掉一批既能跑又有测试的代码——而后端刚刚被修过一轮并补上了契约测试。这是把能用的东西扔掉。
2. **Dashboard 已经在只读地展示词汇了。** 这是一台只能看不能用的机器：数据在那里、界面在那里、唯独没有产生数据的入口。**只读是所有状态里最糟的一种**——它让用户以为功能坏了。
3. **词汇 + 间隔复习是这个产品唯一能自然制造「明天还想回来」的理由。** 第一轮的结论是：产品目前只有「看当前视频的字幕」一个使用理由。字幕是即用即走的，词汇本会积累。
4. **后端已经是生产可用的**，不需要为了接 UI 而新建基础设施。

## Consequences

- 面板需要一个新的 **Words 标签**，包含：词汇列表、划词捕获入口、复习队列。
- 词汇的**产生**路径必须接上：划词捕获（用户在字幕里选中一句话 → 存为词汇）是最自然的形式，和现有的「选中文字 → Note」是同一条交互肌肉。
- Dashboard 现有的只读词汇视图会从「只读」变成「与扩展双向一致」。
- `PRIVACY.md` 必须如实写明同步服务保存词汇条目和复习排期——第二轮已经补上（见 `62fff27`）。

## Alternatives considered

- **彻底砍掉**：需要删 7 个文件 + 4 份文档 + 4 条 ADR/审计引用；会毁掉刚修好的后端；而且会留下一句「这里本来有个功能」。
- **保持只读**：Dashboard 继续展示词汇，但没有任何新词汇能产生。存量数据会腐烂，用户会以为功能坏了。**否决**。
- **只做划词捕获，不做复习**：复习排期已经在后端跑着了，只做捕获会让复习功能继续悬空。**否决**。

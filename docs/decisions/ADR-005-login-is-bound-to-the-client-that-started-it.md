# ADR-005: 登录必须绑定发起它的那台设备

## Status
Accepted（2026-10-20）— 已执行

## Background

OAuth 的回程里，token 是一段可以复制的字符串。以前只要页面上出现
`#access_token=...`，客户端就把它收下来当成登录凭证。

这意味着：**任何一条带 token 的链接，都是一把别人账号的钥匙。**

具体的坏处不是「token 泄露」这么笼统，而是：

- 用户点开一条链接（聊天里的、邮件里的、网页里的），面板就悄悄切到了
  另一个账号；
- 切过去之后，这个账号在本机的笔记、单词、复习进度**跟着显示出来了**——
  别人账号的内容出现在自己的屏幕上；
- 界面上没有任何提示：用户以为自己在看自己的笔记。

登录时用的 `state` 参数挡不住这个：`state` 保护的是**发起登录的那个请求**
不被别人伪造，但 token 落地之后就被复制走了，和 `state` 无关。

## Decision

**服务端把客户端给的随机 nonce 原样带在 token 后面回来；客户端只接受
带自己那份 nonce 的 token，对不上就当作没登录过。**

具体做法：

1. 客户端（扩展、网页面板）在发起登录时生成一个 32 位随机 nonce，存在本机
   （扩展存 session storage，面板存 sessionStorage），并随登录请求一起
   发给同步服务。
2. 服务端把这个 nonce 存进一个 `__Host-` 前缀的短期 cookie，回程时原样放进
   URL 的 fragment：`#access_token=...&nonce=...`。
3. 客户端收到回程时**两个都要对**：token 拿走，nonce 拿去和本机存的那份
   比。对不上（包括根本没有 nonce）就整条丢弃，不写进任何存储。

顺带把这条回程上的其它洞也补了：

- 状态 cookie 换成 `__Host-` 前缀（兄弟子域写不坏它），并且用过一次就
  作废——**换 token 失败时同样作废**，不然同一个 state 能被重放。
- 回调接口加了频率限制。它是公开的，不然谁都能拿这个服务去砸 GitHub 的
  token 接口。
- 面板上那个「按了也没用」的重试按钮去掉了（见 ADR-006 的邻居：不能用
  的按钮比没有按钮更糟）。

## Consequences

- **没有 nonce 的 token 一律被拒。** 这是有意的：宁可让用户重新点一次登录，
  也不能把账号交给别人。代价是「从旧版本复制过来的登录链接」会失效一次。
- 扩展和面板各存一份 nonce。它只活到登录结束，不进用户的数据。
- 面板的登录链接因此不再是纯链接：按下的时候要先把 nonce 写进地址栏。
  键盘和鼠标都能用（改的是链接自己的 href，不是 JS 跳转）。
- 服务端多发一个 cookie。`__Host-` 前缀要求 Secure + Path=/ + 不带
  Domain，正好是这个 cookie 该有的样子。

## Alternatives considered

- **只靠 `state`**：`state` 是一次性的，但它管的是请求，不管 token 落地后
  被复制。**否决**。
- **用 PKCE**：PKCE 防的是授权码被截获后重放，防不住「服务端自己把一个
  token 递给客户端」这一类问题——这里被利用的正是服务端正常发出的 token。
  **否决**（而且我们并不在服务端保管任何客户端秘密）。
- **把 token 放在 URL 的 query 而不是 fragment**：那会让 token 出现在
  服务器访问日志和 Referer 里。fragment 不会发给服务器，保留 fragment。
  **否决**。
- **要求用户每次都手动确认账号**：给一个正常路径加摩擦，并不能替代这
  一层校验。**否决**。

# ADR-007: 上架与部署：代码能做的都做了，剩下的要一个人来做

## Status

Pending（2026-10-22）— 三件事等一个人来定：一次线上部署、一个开发者账号、一个支持邮箱

## Background

第六轮审计（`docs/AUDIT-2026-10-22-R6.md`）把产品当成交给一个不认识它的人来看，
收到 72 条结论，68 条修掉了，两条有意不改，两条要人来定。修掉的那 68 条里，
把产品推到「可以拿得出手」的有三件：

- **商店的五张图和那个 ZIP 现在是产品本身生成的**，不再靠人记得（图是拍出来的，
  ZIP 每个文件跟仓库对过一遍 SHA-256）。
- **同步服务有了增量和一次推完整库两条路**，一个两万条的账号打开面板不用等三秒。
- **文档里的每一句话都有代码撑着**，政策、隐私页、两份 README、安装指南都按
  代码实际在做的事重写过。

剩下的三件事，代码做不了，因为它们要么是**对生产环境的改动**，要么需要一个
**只有人能给的账号或地址**：

| # | 事情 | 为什么代码做不了 | 我的建议 |
| --- | --- | --- | --- |
| 1 | 把 Worker 部署到线上 | 这是动生产环境；而且线上跑的是比仓库旧的代码 | **先做这一件**，见下 |
| 2 | 上架 Chrome Web Store | 需要 $5 的开发者账号、商店名称的决定、支持邮箱 | 等账号和邮箱 |
| 3 | 商店名称里的 `YouTube` 商标 | 商店政策不鼓励在名称里用别人的商标 | 先用 `YouTube Digest: Transcript, Translation & AI Notes`，被打回再换备用的 `Video Digest: ...` |

## Decision

**先部署 Worker，上架等账号和邮箱。**

部署这一步不是「上线产品」，是把**线上服务拉回和仓库一致**。现在线上的
`https://ytd.panbo.space` 跑的还是比仓库旧的代码，三个证据：

- `GET /api/status` 返回 `uptimeSeconds: 1792698808`（约 56 年，其实是 epoch 秒），
  仓库里的代码算的是真正的运行时长；
- `POST /api/sync`（设备一次推完整库）返回 **404**，这个接口在线上根本不存在；
- `GET /api/sync`（增量）存在，但返回的形状里没有 `truncated`，客户端不能判断
  这一次回答是不是被截断的。

也就是说：**仓库里的同步已经写好了，线上却还没有**。客户端的快速路径要等部署
之后才会真的生效。

部署的方式是仓库里现成的一条命令：

```bash
cd server && bash scripts/deploy.sh
```

它先跑迁移再部署。迁移是加列、加索引，`if exists` / `if not exists` 全部带着，
可以重复跑；`server/` 的 264 个测试是对着真的 Postgres 跑过的，schema 与线上同源。

**不上架**，直到三件事齐了：开发者账号、有人看的支持邮箱、名称的决定。
仓库里现在一个 `mailto:` 都没有，商店表单却必填这一项。

## Consequences

- **部署是可回退的。** `wrangler deploy` 覆盖的是 Worker 的代码，不是数据；
  迁移只加不减，出问题可以把上一版代码重新部署回去。
- **部署之后，线上隐私页会和仓库里的政策一致。** 商店表单要填的
  `https://ytd.panbo.space/privacy` 现在还是旧的一页，和 `PRIVACY.md` 差着
  退出登录、删除账号、账号上限、浏览器名字这几处说法。部署是让三者一致的唯一办法。
- **上架那天还有两处文字要改**（README 里「不在商店上架」那句、商店描述里的
  「local install」），`docs/WEB_STORE.md` 里逐条列了，和换名时要改的
  `manifest.json` 的 `name` 放在一起。
- **支持邮箱要么新建一个专用的，要么用你自己的。** 这是一个对外的地址，
  收信的人会看到「支持」两个字，所以代码里和文档里都不应该出现一个假地址。
- **如果部署之后线上出问题**，第一件事是把 Worker 回滚到上一版，而不是改数据。

## Alternatives considered

- **先上架，部署以后再说**：不行。商店审核会打开隐私政策页，页面上写着的
  「退出登录会清掉这台设备上的副本」在旧的那一页里并不成立，而仓库里的政策
  已经改了。审核人看到的是线上那页。
- **把线上的旧 Worker 留着，只上架扩展**：同步服务是扩展的一半（跨设备读笔记、
  复习进度），两半对不上比不卖更糟。
- **用「暂不支持」的名义先上架**：那要多写一套文案、多维护一份代码，
  而缺的是账号和邮箱，不是能力。

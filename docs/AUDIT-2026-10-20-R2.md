## 一、钱：一次普通的操作，用户被扣了两次费

### P0-A　打开一次面板 = 消耗 2 个 Supadata credit（其中一个是白扔的）

**复现方式**（不是读代码猜的，是跑出来的）：用 mock 的 `chrome` API 把 `fetchTranscript` 挂起，模拟真实网络延迟，然后让面板走完真实的启动流程。

```
requestsAfterPanelBoot:            1
requestsAfterNavigationRefresh:    2
totalSupadataCreditsSpent:         2
```

**机制**：

1. 面板打开 → `bootPanel()` → `loadPanelContent()` → `checkCurrentTab()` → `startDigest()` → `fetchTranscript`（第 1 个 credit）
2. 缓存要等字幕**返回之后**才写入（`sidepanel.js` 的 `saveToCache` 在 `startDigest` 末尾）
3. YouTube 页面加载完成触发 `chrome.tabs.onUpdated` → `handleFrontTabUrl()` → `scheduleDigestRefresh()`（600ms 去抖）→ `checkCurrentTab()` → `startDigest()`
4. 此时第 1 个请求还在飞，缓存是空的 → **第 2 个 `fetchTranscript`（第 2 个 credit）**
5. 两个响应都回来，`digestGeneration` 票据让第 1 个被丢弃

Supadata 的定价是「1 transcript = 1 credit」（已对 `supadata.ai/pricing` 核实）。所以**用户每打开一次面板，正常情况下都会多付一个 transcript 的钱**。

### P0-B　付了钱的 AI 概览被扔掉，界面永远卡在「生成中」

**复现方式**：让 `analyzeTranscript` 挂起，用户点开 Overview 标签，然后在 AI 回答之前触发一次导航刷新。

```
paidAnalysisCalls:                         1
chapterListWhileLoading:                   "Generating overview... uses your AI balance"
chapterListAfterThePaidResponseLanded:     "Generating overview... uses your AI balance"
paidWorkWasDiscarded:                      true
```

AI 确实被调用了、确实计费了、确实返回了——然后被 `sidepanel.js` 的票据校验丢弃，Overview 标签**永远**停在「生成中」。

### 根因（两个缺陷是同一件事）

**`digestGeneration` 被当成了「视频变了」的令牌，但它实际是「又跑了一次 digest」的计数器。**

- `startDigest()` 每次被调用都 `++digestGeneration`，**包括再次进入同一个视频**。
- `triggerAnalysis()` 在发起付费请求前抓取 `generation = digestGeneration`，返回后用 `generation !== digestGeneration` 判定「过期」。
- 于是：任何一次重复进入（导航刷新、重试、缓存命中）都会把在飞的付费工作判成过期。

**第二个根因：面板没有「这件事已经在做了」的概念。**

`checkCurrentTab` / `startDigest` / 导航刷新 / 重试按钮各自独立决定要不要开始工作，彼此不知道对方已经开始了什么。票据机制把「结果落到错误的视频上」这个症状遮住了，代价是把**已经付过钱的有效结果**一起扔掉。

**修复方向**：把「视频真的变了」和「又跑了一次」拆成两个概念；并为 transcript / analysis 各建一个按 videoId 索引的在飞请求登记表——同一个视频的第二次请求应当**加入**第一次，而不是再发一次。

### P0-C　Quote 上的「Note」按钮：承诺保存引用，实际什么都没保存，还倒贴一次 AI 调用

**位置**：`sidepanel.js` 的 `saveQuoteAsNote()` / `background.js` 的 `handleSaveNote()`

**问题**：Quote 上的 Note 按钮的 tooltip 写的是「Save this quote as a note」，但它发给后台的 payload 里**没有引用文本**：

```js
await chrome.runtime.sendMessage({
  action: "saveNote",
  videoId: currentVideoId,
  timestamp: quote.timestampSeconds,
  videoTitle: currentVideoTitle,
  channelName: currentChannelName,
});   // <- 没有 quote.quote
```

`handleSaveNote()` 收到没有文本的请求，就走「从缓存字幕里找这一行 → 拼上下文 → 调 AI 清理」的路径。也就是说：

1. 引用原文被丢掉，存下来的是字幕里那一行的文字（可能根本不是那句 quote）
2. **多花一次 AI 调用**去「清理」一条本来就没有内容的笔记
3. 如果 digest 缓存已经不在（20 个视频 / 30 天淘汰），还会**再拉一次字幕**——又多一个 Supadata credit

**修复方向**：把引用原文一起传下去（复用已有的 `selectedText` 直存路径），跳过字幕拉取和 AI 清理。数据模型已经支持 `quote` 字段（`server/src/validate.js` 的 `parseNote` 已经在解析它），只是没人写进去。

### P0-D　换视频之后，上一个视频的章节和引用还留在界面上

**位置**：`sidepanel.js` 的 `startDigest()`

`chapterList` / `quotesList` 只在 `renderAnalysisResults()` 和 `renderAnalysisFailure()` 里被清空。`startDigest()` 在**换视频**时从不清它们。于是：

- 视频 A（有 AI 概览）→ 切到视频 B（还没有概览）→ Overview 标签仍然显示 A 的章节和引用
- 用户在 A 的引用上点 Note → `saveQuoteAsNote()` 用的是 **`currentVideoId`（也就是 B）** → 笔记被记到 B 名下，时间戳却是 A 的

这是**静默的数据错配**：用户以为记下的是「我刚读到的那句话」，实际存到另一个视频的另一个时间点，而且没有任何提示。

## 三、隐私与信任

### P0-E　发布出去的 manifest 向用户索要了一个 localhost 权限

`manifest.json` 的 `host_permissions` 里有 `http://localhost:8787/*`，原本是给本地开发用的。但发布出去的扩展带着这个权限，意味着**用户机器上任何监听 8787 端口的进程都可能拿到用户的笔记和 GitHub 会话令牌**——而且 `PRIVACY.md` 从来没有披露过它。

已修（`829025d`）：manifest 移除该行；`server/SETUP.md` 写明本地开发时如何加回来，以及打包发布前必须去掉。发布门禁会新增一条测试防止它再回来。

同步服务的 schema 有四张表：`users`、`notes`、**`vocabulary`**、**`review_items`**。扩展的 `PRIVACY.md` 只说「你的笔记会被镜像」。词汇条目和复习进度（到期时间、间隔、难度系数）从来没被提及。Dashboard 自己的隐私页写对了，扩展的政策落后了。

## 四、设计与可访问性（进行中）

### 控件边界在浅色主题下几乎看不见

`--border` 在所有表面上的对比度只有 **1.20–1.32:1**，而 WCAG 2.2 SC 1.4.11 要求控件边界达到 3:1。也就是说输入框、按钮、下拉框的边界对不依赖颜色的人是隐形的。

已修（`def9ba5`）：新增 `--border-strong`（浅色 `#96886f` / 深色 `#80756c`，在所有表面上 3.14–3.90:1）专用于功能控件；`--border` 退回纯装饰用途。已应用到 14 处控件边界（sidepanel 7、options 3、dashboard 4），两个主题都用浏览器实测过。

### 搜索高亮标记在浅色主题下只有 2.27:1

`box-shadow: inset 3px 0 0 var(--highlight)` 画在 `--surface-raised` 上，浅色主题 2.27:1（不合格），深色主题 6.68:1（合格）。改用 `--accent` 后两个主题分别是 5.65:1 和 5.50:1。

### 一次自我纠错

我此前记录「四个 translating 状态用 `--text-muted`，对比度只有 4.38:1 / 3.87:1，不合格」——**这个结论是错的**。我假设它们背后有一层 accent 底色，实际并不存在；`--text-muted` 在真实背景上是 4.71–5.66:1，本来就合格。这四处仍然换成了 `--text-secondary`（两个主题都更强），但它们**不是**缺陷，报告里必须写清楚，不能把一次虚惊写成一次修复。

### 复核后确认「不是问题」的三件事（写下来是为了不让下一个人再追一遍）

用真实浏览器（键盘 Tab 遍历 + 读计算样式）复核了焦点可见性，结论是**设计系统是对的**：

| 我一度以为的问题 | 复核结论 |
|---|---|
| 面板里 10 个可聚焦控件里有 8 个「没有焦点指示」 | 假警报。用脚本调用 `element.focus()` 不会触发 `:focus-visible`；改用真实键盘 Tab 之后，**23 个控件全部有可见焦点环**（`2px solid var(--focus-ring)` = #a34732） |
| 若干控件用的是浏览器默认的蓝色焦点环，不是产品 token | 假警报。浏览器缓存了合并前的旧样式表。绕开缓存后重测，全部是产品的 token |
| 字幕搜索框 `outline: 0`，完全没有焦点环 | 假警报。搜索框的焦点环画在**容器**上（`.transcript-search:focus-within` → 边框变 `--focus-ring` + 3px 光晕），这是比只给文字加环更好的做法。实测 `border-color: rgb(163,71,50)`、`box-shadow: rgba(163,71,50,0.35) 0 0 0 3px` |

> 测量本身也会骗人。第一次量到「没有焦点环」是因为在 0.18s 的过渡动画中途读的样式；等到动画结束再读，值是对的。**和变异测试同一个道理：先确认测量真的测到了你要测的东西，再相信结论。**

## 六、同步：用户的编辑不会再被设备时钟吃掉

**这一条是第二轮最有价值的修复之一**，因为它的失败模式是**静默丢数据**。

同步服务用服务端时间戳和本地时间戳比较谁更新。两者从来没有被放在同一条时间轴上：
服务端时间由服务器打，本地时间由设备钟打。设备钟偏快 → 每次同步都判定「本地较新」→
用户刚在 Dashboard 上改的笔记被扩展里的旧副本**静默回滚并覆盖回云端**（网页上写的东西
彻底没了）；设备钟偏慢 → 每次都判定「云端较新」→ 用户当场记下的笔记**静默消失**。

**做法**：

1. 服务端在所有同步响应里带 `serverTime`。
2. 客户端用「请求发出 → 响应到达」的中点估算本地钟，算出 `offset = serverTime - 本地钟`，
   持久化到 `ytd_clock_offset`，合并时用 `localMs + offset` 归一化后再比。
3. **向后兼容**：老服务器不返回 `serverTime` → 退回原来的裸比较，不崩、不改行为。
4. **偏移异常（>±1 天）时不猜**：两边都不覆盖、不推送，控制台告警。覆盖任何一边都是
   不可逆的数据丢失，所以宁可让冲突留到时钟可信之后再解决。

**收藏标记不再被顺手抹掉**：本地笔记记录 `starredSynced`（服务端最后确认的值）作为基线，
只有与基线不同才上传；文字编辑完全不带 `starred`。服务端新增 `/star` 接口，收藏标记
从此有了自己的通道（`setNoteStarred`），不再搭便车走「更新正文」的路径。

**跨账号不再互相继承**：迁移改成「先复制进账号命名空间 → **立刻**清空未登录桶 → 记录
归属账号」，不再等同步成功。失败时笔记仍在原账号的命名空间里，下次补传。

8 个变异全部被测试抓住（忽略偏移 2 个、采信不可信偏移 1 个、总是发 starred 3 个、
忽略本地收藏改动 1 个、不清空未登录桶 2 个、越权导入 1 个、服务端不发/发错 serverTime 2 个）。

## 七、Dashboard：标签栏在骗人，而这里一行测试都没有

第二轮原本只审扩展和后端。我顺手把 Dashboard 也当产品审了一遍——它是用户
同步之后**唯一能看见自己全部数据**的地方。结果发现的东西和扩展里的一样严重。

### P0-F　标签栏说「Notes」，页面上四个面板全在

**复现方式**：用 mock 的 API 加载真实的 `server/dashboard/index.html` 和 `app.js`，
登录，然后读 DOM。

```
afterSignIn.visible:  ["notesPanel", "favoritesPanel", "vocabularyPanel", "reviewPanel"]
afterSignIn.selected: ["true", "false", "false", "false"]
```

**机制**：`showSignedIn()` 把四个面板**全部** `hidden = false`，然后就结束了。
`switchTab()` 会设置面板可见性，但登录流程从来没调用过它。于是：标签栏把
「Notes」画成选中状态，页面上却把 Notes、Favorites、Vocabulary、Review
四块内容堆在一起。用户点一下标签，刚刚在读的三块内容就消失。

**已修**（`8264ce6`）：`showSignedIn()` 改为调用 `switchTab("notes", { reload: false })`，
只显示选中的那个。

### P1-F　复习卡不是控件，键盘用户永远看不到答案

Review 标签的答案藏在卡片里，卡片上只有一个 `click` 处理器——是个
`<div>`，没有 `role`、没有 `tabindex`、没有键盘处理。

```
reviewCardRole:      null
reviewCardTabindex:  null
reviewCardAria:      null
```

读屏用户能听到这张卡，但按不动它；键盘用户根本到不了它。**答案在服务器上
排着队等着被打分，而用户看不到。**

**已修**（`8264ce6`）：卡片改成真 `<button>`，加 `aria-expanded`，并加了一行
「Show answer」提示——`cursor: pointer` 对鼠标用户不算提示。

### P1-F'　Dashboard 的标签栏没有 ARIA 语义

侧边栏上一轮已经补上 `role="tablist"` / `role="tab"` / `role="tabpanel"`、
`aria-selected`、roving tabindex、方向键移焦点。Dashboard 还是一组普通按钮。
**同一个产品不该有两套可访问性标准。**

**已修**（`8264ce6`）：Dashboard 补齐同一套。方向键同样只移焦点不切页。

### P2-F　两处把数据库内部值直接给用户看

- 词汇状态显示 `learning` / `reviewing` / `mastered`（数据库枚举原值），
  和周围全是句首大写的界面不一致。改成 Learning / Reviewing / Mastered。
- 笔记卡片显示 `dQw4w9WgXcQ`（videoId）。这是数据库主键，对用户没有任何
  信息量。改成频道名——schema 里本来就存了 `channel_name`，只是从来没用过。

### 最关键的一条：Dashboard 之前**一行测试都没有**

上面这些 bug 之所以能上线，是因为 Dashboard 的 463 行 `app.js` 从来没有被
任何测试执行过。扩展的测试套件在第二轮被重写过，**Dashboard 被整个漏掉了**。

**已修**（`8264ce6`）：新增 `server/tests/dashboard.test.js`，用 jsdom 跑**真实的**
`app.js`（`runScripts: "outside-only"` + 手动 eval + 手动派发 `DOMContentLoaded`），
9 个用例全部按行为断言：面板可见性、aria 状态、方向键、键盘揭示答案、下拉文案、
卡片元信息。

8 个变异全部被抓住：把四个面板又设成可见、去掉 `aria-selected`、去掉 roving
tabindex、把复习卡变回 `<div>`、下拉文案改回原始值、卡片改回显示 videoId、
去掉方向键处理、不再揭示答案——每一个都会让测试变红。

> 这一条也是对「第二轮做法」的自我验证：**测试套件本身要接受审计**。第一轮
> 审的是「产品有没有 bug」，第二轮审的是「测试能不能抓住 bug」。Dashboard
> 证明了两者都得做——它既没有被审过，也没有被测过。

## 八、后端：两段 SQL 在生产上根本跑不起来

这一节的结论来自一轮专门的「重新复核」，复核的人拿**真实 Postgres 16**（不是
测试替身）重跑了每一条 SQL。

### P0-G　`updateNote` 发出的是 Postgres 无法执行的语句

**位置**：`server/src/db.js` 的 `buildUpdateStatement()`（:67-83）与
`NeonStore.updateNote()`（:542-581）

**机制**：`buildUpdateStatement` 用一个 `lead` 变量在「赋值片段」和「WHERE 子句」
之间滚动。最后一个赋值的 `after` 是分隔符 `", "`（本来是给**下一个**片段用的），
而第一个 WHERE 子句的 `before` 是 `" where id = "`，于是拼出来的是：

```sql
update notes set note = $1,  where id = $2 and user_id = $3
--                                             ^^^^^^^^ 悬空的逗号
```

**三个缺陷叠在同一个方法上**：

1. **没有 `returning` 子句** → `rows.length === 0` → 方法返回 `null` → 路由抛
   404「Note not found.」——**哪怕这次更新其实成功了**。
2. **悬空逗号** → 只要这次 patch 不带 `starred`，语句就是语法错误 → 500。
3. **没有 `updated_at = now()`** → 增量同步（`updated_at > since`）永远看不到
   这次编辑，其他设备上的副本是旧的。`MemoryStore` 却会更新时间戳——**两个
   store 的行为现在不一致了**。

**用户损失**：在扩展里改一条笔记 → `PATCH /api/notes/:id` → 稀疏 patch 永远
500，带 `starred` 的 patch 永远 404（但行其实被改了）。客户端把错误吞掉
（`cloud-sync.js:91-94`）并报告「已保存」，所以**界面上说存好了，服务端其实
没收到**。改动只能靠之后的全量同步补上去，而且还得设备时钟对得上。

（Dashboard 不受影响：它只调 `PATCH /api/notes/:id/star`，那条路径有
`returning` 和 `updated_at = now()`。）

### P0-H　`countRows` 把表名当成绑定参数

**位置**：`server/src/db.js:752-757`

```js
select count(*) as count from ${table} where user_id = ${userId}
```

在 Neon 的 tagged template 里，**每一个插值都会变成绑定参数**（`$1`、`$2`…）。
表名是**标识符**，不能被绑定。于是发出去的是：

```sql
select count(*) as count from $1 where user_id = $2
-- ERROR: syntax error at or near "$1"
```

**用户损失**：`GET /api/export` 对**每一个用户**都是 500。Dashboard 的
「Export my data」按钮和「下载我的数据」这条路径是死的。

### 为什么 111 个测试全绿

`server/tests/helpers/fake-sql.js` 把两个都遮住了：

- count 分支用 `/count\(\*\)\s+as\s+count/` 匹配，然后**从语句文本里猜表名**，
  `from $1` 就悄悄回落到 `notes`，永远不会报错；
- update 分支把 SET 子句拆开、**按语句的形状作答**，所以悬空逗号和缺失的
  `RETURNING` 都是不可见的。

**结论**：`store-contract.test.js` 的 NeonStore 那一半校验的是**查询的形状**，
不是**可执行的 SQL**。整个 NeonStore 路径**从来没有被真正的 Postgres 执行过**。
这和扩展侧「源码正则断言」是同一类问题，只是发生在后端。

## 九、本地化：三个界面里有两个是纯英文

产品的中文不是「附带的翻译」，是**一等公民**：面板和设置页都有完整的
English / 简体中文，README 有中文版。但：

| 界面 | 状态 |
|---|---|
| 侧边栏 | ✅ 完整双语 |
| 设置页 | ✅ 完整双语 |
| **内容脚本**（YouTube 页面上的浮层按钮） | ❌ **全英文** |
| **Dashboard** | ❌ **全英文** |
| 隐私文档（`PRIVACY.md` / `privacy.html`） | ❌ 仅英文 |

### 一个更细的缺陷：中文文案用英文标签指路

设置页的中文引导写着「**点 Overview** 查看 AI 摘要」——但中文面板里那个标签
叫「**概览**」。侧边栏的「还没有笔记。把鼠标移到视频上并点击 **Note** 即可保存。」
同理：中文界面里根本没有一个叫 "Note" 的东西。

**根因不是漏翻译，是硬编码**：文案把界面元素的名字写成了英文字面量，而不是
用用户真正看到的那份名字。

**已修**（`dd65f90`，设置页）：复制表新增 `tabTranscript` / `tabOverview` /
`tabNotes`，`translate()` 支持 `{name}` 插值，文案写 `{tabOverview}`，渲染时
填入当前语言下的真实标签名。新增两个守卫：设置页和侧边栏对标签页的叫法必须
一致（两个页面没有共享模块，会漂移），以及中文文案里不许出现英文界面元素。
4 个变异全部被抓住。

顺带修掉设置页中文里的 6 处半角标点（「配置完成!接下来:」这种）——侧边栏一直
用全角，设置页混用半角，两页看起来像不同的人写的。

**内容脚本和 Dashboard 的本地化在处理中。** 隐私文档**故意没有动**：一份隐私
政策的机器翻译是**合规决策，不是代码改动**，留给产品负责人拍板。

### 踩坑记录（重要，避免重犯）

1. **`git fetch` 在本机沙箱内会被 SIGTERM 杀死**（SSH 卡在 sideband packet），必须给 Bash 传 `dangerouslyDisableSandbox: true`；且完整 fetch 仍会断，需 `--depth=60` 浅拉取才能成功
2. **不要用 `git checkout --conflict=merge` 重置已解决的文件** —— 它会把 `<<<<<<< HEAD` 改写成 `<<<<<<< ours`，之前按 `HEAD`/`upstream/main` 写的批量替换脚本全部失效，需重做
3. **机械"保留双方"拼接测试文件会截断代码块**：冲突块边界不完整时，`keep both` 会产出语法错误（`Identifier 'result' has already been declared`）。正确做法是用 `git show HEAD:file` 取回完整原文按测试名边界替换
4. `git merge-tree --write-tree --name-only A B` 可无副作用预演冲突，返回 tree hash + 冲突文件列表，比 `git merge --no-commit` + abort 更安全

### 踩坑记录（协作侧，重要）

**多 agent 并行写同一工作目录会互相破坏**：三个 agent 共用 `/Users/panbo/Code/Demos/youtube-digest`，各自 `git switch` 分支导致 HEAD 互相覆盖；其中一方执行 `git stash -u` 把他人未提交改动移走。

正确做法（下次务必遵守）：
1. 每个 agent 用**独立 worktree**：`git worktree add -b <branch> /tmp/<name> <base>`
2. 门禁复核也在 worktree 里做，不碰主工作区
3. 主 agent 统一在 `integrate/*` 分支上 merge 各成果

**另一个坑**：合并多分支后检查成果时，`grep -c` 大小写或表达式写错会误判"改动丢失"。必须用多个命名变体交叉验证（本例 `SYNC_SESSION_EXPIRED` vs `sync-account-expired` vs `expired`），或直接读函数体。
